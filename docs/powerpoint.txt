標準化について
・特徴量を公平に比較できるように平均0　標準偏差1にする 
→A1だけとB2だけを比較できる、しかも、8.00と-0.5などがごっちゃにならない 
→正規化すると勾配降下法に便利 　☆単変量（列）と多変量（列ごと） 　？
機械学習はそれぞれの特徴量の重みを2乗和して計算する
→全部標準化しないと意味なくない？引っ張られるみたいにならない？ 

LeCun et al. (1998) "Efficient BackProp" 
・各特徴量の平均を0に近づけるべき 　
・すべての特徴量の分散（標準偏差）を等しくすべき 　　
→標準化 　
・特徴量どうしの相関をなくす 
・sigmoidよりもtanhにする
① 無関係なラベルのとき そもそもデータがすべてプラスだと学習が進まない 
→平均0にしたい 例えば４つだと [1, 0, 0, 0]
→[ 0.75, -0.25, -0.25, -0.25] [0, 1, 0, 0]
→[-0.25, 0.75, -0.25, -0.25] [0, 0, 1, 0]
→[-0.25, -0.25, 0.75, -0.25] [0, 0, 0, 1]
→[-0.25, -0.25, -0.25, 0.75] 平均を引いて標準偏差で割る 

② クラスのように関係があるラベルのとき 1, 2, 3, 4として平均を引いて標準偏差で割る
Bishop (2006) "Pattern Recognition and Machine Learning" (PRML) 　
・パラメータを確率分布として求める 　
・標準化 
・cross validationなどを使って公平に検証を行う
 ・二乗誤差損失を用いた場合の期待損失がバイアス、バリアンス、ごみ

①    何号艇が何着でゴールするか
問題点
GBDTにとっては「1と2の差」も「1と6の差」も同じ「間違い」として扱われる

①カスタム損失関数を導入する
1着が正解のときに「2着」と予測したらペナルティ 1、「6着」と予測したらペナルティ 10 という風に重み付けをする
→損失関数の1, 2回微分を重みづけありでコードに書く必要があり、非常にめんどくさい　トライ＆エラーがめんどくさい
②ラベルスムージング
１着が正解のラベルの時、従来は[1.0, 0, 0, 0, 0, 0]としていたが、[0.8, 0.15, 0.03, 0.01, 0.01, 0.00]のように、２着にも重みをつける
→トライ＆エラーがめんどくさい

② 各艇が1着になる確率
３連単 i-j-k が当たる確率を考える　（iがw着になる確率をP(i, w)とする）





単勝モデル：   P(Top1i​) …  i号艇が1着に入る確率
2連対モデル： P(Top2i​) … i号艇が2着以内に入る確率
3連対モデル： P(Top3i​) … i号艇が3着以内に入る確率
P(i,1) = P(Topi​)
P(i,2)raw​=P(Top2i​)−P(Topi​)
P(i,3)raw​=P(Top3i​)−P(Top2i​)
と計算できる
面倒な設定をせずに、結構うまいこと行きそう


Harvilleの式
３連単 i-j-k が当たる確率 P(i-j-k)　≈　P(i,1)　×　P(j,2) / 1−P(i,2) ​  ×   P(k,3)​ / 1−P(i,3)−P(j,3)

③ 6艇の中の相対的な強さを見る
問題点１
ランキング学習における評価指標の複雑さの問題
nnの疑似的な勾配法のように順位を変え、スコアの最大値を見ているが、スコアの計算式が、上位のミスには厳しく、下位のミスには寛大になっているため、順位を変えただけでスコアが大きく動いてしまい、迷子になりやすい
→学習率を極限まで下げる or  softmax関数などで各艇が1着になる確率として扱う

問題点２
②圧倒的な差と僅差の区別がつかない
１> 2 > 3という予測の時、1が独走しているのか、ハナ差で1が勝ったのかが読み取れない
→正解ラベルの数字をタイムの差にする or 独走のレースや僅差のレースで与えるスコアを変化させる

④ レースタイムを予測（回帰）
メリット１
レースタイムで見ているため、しきい値による振り分けに強い
・風速が 4.9m までは影響が少ないが、5.0m を超えた瞬間に、1コースの旋回が膨らんでタイムが 0.3 秒落ちる
・ある温度帯（例：15∘C 前後）が最もタイムが出やすく、それより高くても低くても遅くなる

などの線形ではない現象を把握できる
メリット２

順位だと反応しないようなわずかな差をレースタイムによって見つけれる
点の順番ではなく、数直線上の値で見ているため、
条件A：気温が 30度　条件B：湿度が 80% 以上　条件C：モーター番号が「良機」ではない
などでおこる複雑なかけ合わせにも反応できる


④ レースタイムを予測（回帰）

問題点１
決定木は段差の集合体なので、0.01秒の差をとらえられない
→TabNetなどnnっぽいモデルを使う　そこまで問題ではなさそう

問題点２
転覆や出遅れなどに影響を受けてしまう
→ある一定の閾値までとそれ以降で、損失関数を変える or 各会場ごとに平均タイムを取り、平均タイム + 7σ以上時間がかかっているデータを消す
＊7σなら、正規分布ですらない分布を想定しても、異常値を2％以下に抑えられる

検証方法について
K-fold CV, Stratified K-fold CV リークの可能性がある　ないかも...　たった１レースを予測するだけだし

time-serires CV　モーターの性能変化や節の入れ替わりを挟まないと、今このモーターが強い　という風に間違えて学習してしまう
学習データが足りないことや、期間によって偏りが出てしまうかも

期待値を算出して、ベッティングルールを決める
